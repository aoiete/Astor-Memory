给 Agent 装上"记得住、想得起、改得动"的记忆，已经从加分项变成标配。本文把 2026 年主流的六条记忆技术路线拉到同一张桌子上，从表示、写入、检索、更新、成本五个维度做横向对比，并给出一张选型决策表。

一、上下文窗口再大，也替代不了记忆

过去两年，上下文窗口从 32K 涨到百万 token 级，一种流行观点是："把所有历史都塞进上下文，记忆问题自然消失。"但工程实践很快撞上三座大山：

成本
：历史每多一轮，每一步推理都要重复付费。Prompt Caching 能缓解、不能消除，长对话的成本曲线依然随时间线性增长；

噪声
：长上下文存在"中间遗忘"（lost in the middle）现象，关键事实埋在几万 token 里，召回率随长度衰减；

生命周期
：真实产品需要跨会话、跨设备、跨月份的持续状态——今天记住你上周说过的话，下次会话上下文里并没有它。

所以记忆的本质定义是：跨会话持久化的用户与任务状态，加上按需召回的能力。这也解释了为什么 2024 到 2025 年间，Letta（MemGPT）、Mem0、MemOS、MemU 等一批"Mem-X"框架集中爆发，而到 2026 年，记忆层（Memory Layer）已经成为 AI 应用栈里与模型、RAG、工具调用并列的标准组件。

二、六条主流技术路线

路线 1：全量上下文（Full Context）——"最好的记忆是不遗忘"

做法：不做任何抽象，把全部历史原文塞进上下文，配合 Prompt Caching 控制成本。

代表：各类长上下文模型的原生长对话；早期 Cursor、Claude Projects 等产品形态。

优点是零信息损失、没有抽取偏差、工程最简单，模型能力的提升会自动转化为记忆能力。缺点是成本随历史线性增长；长上下文召回率衰减；跨会话依然无解——下次会话仍然从零开始。

值得注意：2026 年出现了不少"反方研究"。有独立分析发现，足够强的模型开启全量上下文后，在 LoCoMo 等基准上可以反超部分记忆产品（例如 81.69% 对 92.85%）。"记忆层跑不赢全量上下文"是一个真实存在的质疑，但对几十轮以上的真实产品，全量上下文的成本曲线和召回衰减决定了它只能是基线，不是终局。

路线 2：上下文压缩与结构化笔记（Compaction & Notes）

做法：会话内做摘要压缩（compaction），跨会话把关键约定写入结构化笔记文件，需要时再读回来。

代表：Claude Code 的自动压缩与 CLAUDE.md / AGENTS.md；Anthropic 官方 memory tool（2025 年 9 月随 API 推出，文件式记忆 + 上下文编辑）；Manus 的"把文件系统当记忆"（todo.md 复述、结果落盘）；ChatGPT 的聊天历史引用（reference chat history）。

特点：LLM 自己决定记什么，人以文件形式直接可见、可改、可版本管理。粒度偏粗，本质是"工作记忆外置"，对编码、办公类 Agent 特别有效——项目约定、代码规范、任务清单，一篇 Markdown 就够了。

局限：文件结构没有 schema 约束，规模一大就会乱；检索靠路径和全文匹配，没有语义召回保证；"记什么、删什么"完全依赖模型自觉。

路线 3：向量检索记忆（RAG-style Memory）

做法：对话切片、embedding 入库，检索时按语义相似度召回 top-k 拼进上下文。

代表：MemoryBank（2023，引入艾宾浩斯遗忘曲线与重要性加权）；Generative Agents 的记忆流（recency × importance × relevance 三重打分，是一切加权检索的祖师爷）；以及无数 LangChain/VectorStore 自制方案。

优点：实现简单、语义召回泛化好、成本可控。缺点：切片原子化之后丢失时序与因果；新旧事实冲突无解——"我搬去上海了"和"我住在北京"会同时被召回；检索质量高度依赖 embedding 质量与查询改写。

这是所有记忆系统的底座，但 2026 年的共识是：单独用向量检索，已经不够了。

路线 4：记忆抽取与生命周期管理（Agentic Memory Pipeline）

做法：记忆不再是"存对话"，而是"持续维护一条条可更新的事实"。写入时用 LLM 抽取候选记忆，与库中已有记忆比对，再决定执行 ADD / UPDATE / DELETE / NOOP 哪种操作。

代表：

Mem0
（2024-2025）：两阶段"抽取-更新"流水线的代表。论文报告在 LoCoMo 上相对 OpenAI 内置记忆提升约 26%，p95 延迟比全量上下文低约 91%（1.44s），另有可选的图变体；

LangMem
（LangChain）：按语义/情景/程序三类记忆组织，区分热路径（即时写入）与后台处理（异步巩固）；

A-MEM
（2025）：Zettelkasten 卡片盒思路，每条记忆是一张带关键词、标签、上下文描述的"卡片"，新记忆写入时自动与旧记忆建立链接并触发相邻记忆演化，检索时能"顺藤摸瓜"；

MemU
（2025-2026）：把记忆组织成文件夹与文件，检索导向的增量更新，并用训练过的小模型专门执行记忆操作来降本。

优点：事实级粒度；支持冲突消解与知识更新；每条记忆可读、可删、可审计，解释性好。缺点：每条消息都要过 LLM 抽取，写入延迟和成本不低；抽取质量决定上限；错误的更新一旦写入，回滚困难。

这条路线是当前创业公司产品化最集中的地带（Mem0 Cloud、Supermemory 等），也是大多数团队"给产品加记忆"时的默认起点。

路线 5：时序知识图谱（Temporal Knowledge Graph）

做法：把事实建模为"主体-关系-客体"三元组，每条边携带双时态（bi-temporal）信息——事实在现实世界的有效期（t_valid / t_invalid）与系统感知到它的时间（t_created）。检索时沿图多跳遍历。

代表：

Zep / Graphiti
（2025）：双时态知识图谱的代表。旧事实不被物理删除，而是被标记失效，天然支持"当时对、现在错"的时间推理；

HippoRAG 2
（2025，ICML）：以海马体索引理论为蓝本，离线用 LLM 构建开放知识图谱，检索时用个性化 PageRank 做多跳扩散，是神经生物学启发的检索标杆；

Cognee
：开源的"抽取-认知-加载"管道，向量与图谱混合存储。

优点：多跳关系推理强（"我同事的太太所在的公司"这类问题）；时间演进被显式建模；对组织、人员、项目关系密集的企业场景几乎是必选项。缺点：构建维护成本最高——实体消歧、图更新、schema 漂移都是持续的工程负担；查询延迟高于纯向量；对轻量闲聊场景明显过重。

趋势是与路线 4 融合：Mem0 提供图变体，Zep 底层同样是"图 + 向量"混合检索。

路线 6：分层记忆系统 / 记忆操作系统（Memory OS）

做法：不把记忆当一个库，而是当一个调度系统——借鉴操作系统的分页、调度与虚拟化思想，在模型参数记忆、外部长期记忆、上下文工作记忆之间自动搬运信息。

代表：

MemGPT / Letta
（2023 论文 → 2024-2025 公司化）：虚拟上下文管理，主上下文与外部存储之间自动分页，Agent 通过工具调用自主管理记忆；2025 年提出 sleep-time compute——空闲时段离线整理记忆、预计算索引，把"记"和"想"在时间上解耦；

MemOS
（2025）：提出 MemCube 统一封装明文记忆、KV 缓存记忆与参数记忆三类形态，负责记忆的调度、迁移与生命周期治理，试图做 LLM 世界的"记忆操作系统"；

ChatGPT 记忆
可视为产品侧的简化参照：显式的 saved memories 卡片 + 全局的聊天历史引用，双层结构。

优点：上限最高。参数化记忆——用知识编辑把稳定事实写进权重——只有这条路线能容纳；推理时的调度也最智能。缺点：复杂度天花板同样最高，工程门槛对中小应用不友好，MemOS 一类系统的收益在中小规模下尚不明显。

四、评测基准与那场"要不要记忆层"的争论

当前记忆系统的事实标准评测有两个：

LoCoMo
（2024）：数百轮、跨最多 35 个会话的超长对话问答，考察跨会话记忆保持；

LongMemEval
（2024，ICLR 2025）：约 500 个问题，系统性地拆成五种能力——信息抽取、多轮推理、时序推理、知识更新、拒答，是目前区分记忆系统好坏的最细尺子。

正方数据：Mem0 论文报告 LoCoMo 相对 OpenAI 内置记忆提升约 26%、p95 延迟低约 91%；Zep 报告 LongMemEval 上显著优于全量上下文基线。

反方数据：2026 年的多项独立分析显示，足够强的模型开全量上下文，在 LoCoMo、PersonaMem 等基准上能反超部分记忆产品；抽取式记忆还存在"错误更新→不可逆污染"的独有风险。

比较公允的结论是：记忆层的价值不在跑分碾压全量上下文，而在三件事——成本-质量-时延的帕累托改进、跨会话的持久状态、以及可编辑可审计的治理能力。另外提醒一句：主流评测的对话长度普遍只有几十轮，而真实产品的对话是几百上千轮的，任何基准分数都只能当参考系，不能当承诺。

五、选型建议

按场景对号入座：

个人工具、对话轮次少
：Prompt Caching + 全量上下文，别过度设计；

编码/办公 Agent
：结构化笔记路线——CLAUDE.md 式 memory files + Anthropic memory tool 的思路，成本最低、可控性最好；

C 端个性化助理
（记住画像、偏好、历史决定）：Mem0 / LangMem 式抽取管线起步，向量检索打底，冲突消解必须做；

企业知识密集型 Agent
（组织、人、项目关系复杂）：Zep/Graphiti 时序图谱 + HippoRAG 2 式多跳检索；

平台级、多租户、亿级用户
：认真考虑 Letta / MemOS 式分层架构，把记忆治理当作一等公民。

三条通用原则：记忆必须可解释（每条能被人看懂）、可编辑（错了能改）、可遗忘（用户要求删除时真能删干净——这在个人信息保护法与 GDPR 语境下不是加分项而是合规项）。最后，把记忆当"产品功能"设计，而不是当"存储问题"解决。

六、2026 年值得盯的五个方向

记忆操作模型专用化
：用训练过的小模型专门做抽取与更新，替代"每条消息都调大模型"，MemU 已在验证这条路；

睡眠时整理
（sleep-time compute）：空闲时段离线巩固、去重、预计算索引，Letta 的方向；

参数化记忆回归
：知识编辑把稳定事实写进权重，与外部记忆混合调度，MemOS 的参数记忆容器是信号；

记忆互操作标准化
：MCP memory server 等尝试让记忆层像数据库一样可插拔、可迁移；

记忆治理与合规
：遗忘权、跨用户隔离、记忆审计——企业采购记忆层时最先问的三个问题，大概率都在这里。
