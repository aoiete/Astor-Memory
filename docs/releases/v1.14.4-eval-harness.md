## Ship — Phase 5: source ↔ runtime sync (重要学习!)
- `memory_servers_watch.py` 是 NSSM 服务启 memu/mempalace 的 watchdog,
  **不 watch astor**。astor 是 `start_astor.sh` bash script 启的。
- 直接改 source 的 server.py → server 不重启,改动不生效。
- **必须**:改 source → `shutil.copy2(source, runtime)` → user 手动重启 server
  (或者等 start_astor.sh 重跑,无自动 reload 机制)。
- astor 没有 auto-reload 机制,server 重启依赖 user 手动触发或 start_astor.sh 重跑。

## Lessons (R-class)
- **R-class A**: sweep 一次结果不能 lock config — 多次 sweep 同样 noisy (R-class A2)
- **R-class B**: source↔runtime 必须 sync, watch 不管 astor,user 启的进程需手动重启
- **R-class C**: eval_runner 加 retry 防 server 中途崩导致大量 unknown
- **R-class D**: expected_keywords 是 list[str],合成时别把 min_hits int 混进去
- **R-class E**: 修 still-miss 优先 re-keyword(用 fact 字面词),不要 re-write query
- **R-class F**: 中英双语 query 能绕开英文 embedding 模型的语义 gap (Q45/46)
- **R-class G**: 中文 embedding 换 bge-m3 是大改 (9500+ facts 重 embed), ROI 待评估
