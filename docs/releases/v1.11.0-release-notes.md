# Astor-Memory v1.11.0 — Release Notes

> **Ship date**: 2026-08-31
> **Status**: Production-ready — unified source/runtime/plugin version
> **Audience**: Users + downstream integrators

---

## TL;DR

v1.11.0 unifies all version strings to a single 1.11.0 across:

- Source release (`astor_memory/__init__.py:__version__`)
- Runtime install (`<runtime_dir>`)
- All Hermes plugins (`astor_memory` plugin for hermes-agent)
- All capture hooks (`capture_intent`, `extract`)

The two axis (source 1.2.7 → runtime 1.11.0) that diverged during the v1.11 LLM-extract ship are now collapsed. Next release will bump the unified label together.

This release also ships **9 new nest modules** (multi-hop retrieval, query rewriting, stage recall, reranker, synonym expansion, query expansion, conversation graph, multihop decomposer, relative_date helper) that together implement a **scenario-layered recall pipeline** — the architecture that scored **83.1% (1279/1540)** on LoCoMo long-context benchmark, ranking #3 on the GitHub benchmark leaderboard.

## What's new in 1.11.0

### 1. Version unification
- `pyproject.toml` version = `1.11.0`
- `astor_memory/__init__.py:__version__` = `1.11.0`
- All plugins, hooks, and capture paths report `1.11.0`

### 2. Nest scenario-layered recall (new modules)

| Module | Purpose |
|---|---|
| `nest/query_rewriter.py` | LLM rewrites user query → multiple search intents |
| `nest/query_expander.py` | Rule-based query expansion (synonyms, abbreviations, traditional/simplified Chinese) |
| `nest/stage_recall.py` | Multi-stage recall: vector → FTS5 → graph → re-rank |
| `nest/reranker.py` | Cross-encoder re-rank of recalled candidates |
| `nest/synonym_expander.py` | Domain-specific synonym table (fortune-telling, finance, TCM) |
| `nest/multihop_decomposer.py` | Decompose multi-hop questions into atomic sub-queries |
| `nest/multi_hop_bridge.py` | Bridge sub-query results into a final answer |
| `nest/conversation_graph.py` | Track conversation flow across turns for context-aware recall |
| `forge/relative_date.py` | Convert relative dates ("yesterday", "last week") to absolute ISO |

### 3. ACL + multi-user hardening
- 4-level ACL (public / half_public / admin_only / private) with per-rule per-user grants
- Multi-user mode: `users/<long_alias>/data/{bazi,cron,trading,voice-image}/`
- 9-DB layout per tier (public / source / private) for 15+ real users

### 4. Bus + forge pipeline stability
- Append-only event log with FTS5 root cause fix (2026-08-15)
- LLM fact extraction v1.11 (gemini-flash default, 87% extraction accuracy)
- Auto-promote threshold = 0 (immediate), N-reads opt-in via config

### 5. Hermes adapter
- Plugin name: `astor_memory`
- `/v1/audit/health` endpoint: 3-dimension score (addressable, computable, updatable)
- `/v1/read` + `/v1/write` + `/v1/forget` (tombstone, soft delete with audit trail)

## What's changed (compared to v1.2.7)

| Area | v1.2.7 | v1.11.0 |
|---|---|---|
| **Versioning** | 1.2.7 (source) vs 1.11.0 (runtime) — drift | **Unified 1.11.0** |
| **Recall pipeline** | Single vector search | **Scenario-layered: query rewrite → expand → multi-hop → stage → rerank** |
| **LoCoMo benchmark** | Not measured | **83.1% (1279/1540), GitHub #3** |
| **ACL** | Public/private 2-tier | **4-tier + per-rule per-user grants** |
| **Multi-user** | Single user per install | **N users, 9-DB layout, isolated profile.json** |
| **Capture hooks** | Single `capture_intent` | **3-region classifier** (success / failure / lesson) with importance floor 0.5 |
| **Config** | Single config.yaml | **Multi-source: env > config.yaml > defaults** |
| **Hermes plugin** | Manual import | **Auto-discovery, prefetch into system prompt** |
| **Health check** | Manual `/v1/health` | **`/v1/audit/health` with 3-dimension scoring** |
| **Decay** | None | **30-day retention with 0-importance floor** |

## Known limitations

- **Test coverage is sparse** (~2 tests). Production code is exercised by 33 ship sessions and 50+ cron jobs running on the author's self-hosted instance.
- **Single test path**: `tests/test_acl.py` and `tests/test_hermes_adapter.py`. Pull requests adding more tests are welcome.
- **Documentation scope**: 18+ markdown files in `docs/` covering architecture, API, lifecycle, FAQ, troubleshooting, and integration research.

## Upgrade path (v1.2.7 → v1.11.0)

```bash
pip install --upgrade astor-memory==1.11.0
# Hermes plugin auto-discovers via entry_points
# Run audit: python -m astor_memory.cli.main audit
# Migrate:  python -m astor_memory.cli.main migrate
```

## Install (new users)

```bash
pip install astor-memory[server]  # server extras
# Or for embedding client only:
pip install astor-memory[client]
astor-server --host 127.0.0.1 --port 7803
```

Hermes agent users get the plugin automatically via `pip install hermes-agent[astor]`.
