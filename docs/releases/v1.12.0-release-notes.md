# Astor-Memory v1.12.0 — Release Notes

> **Ship date**: 2026-09-01
> **Status**: Production-ready — ACL hardening + PII cleanup pass

---

## TL;DR

v1.12.0 is a security-and-cleanup release. It contains **no user-visible
feature changes**; it only makes the existing ACL stronger and removes
several pieces of operator-private data that were committed to the
public source tree in earlier releases.

### What changed (4 buckets)

1. **ACL v1.2 hardening** — see `docs/acl-v1.2-hardening.md` for the
   long-form explanation. Summary: actor validation, public-write lockdown,
   user_id=None raise, re-init audit, async-safe contextvars, per-target
   leaky bucket rate limit, path traversal defense.

2. **PII cleanup** — removed hardcoded operator data from source. Any
   production bot IDs, real birth dates, real 八字 pillars, hardcoded
   user chat-ids, and hardcoded absolute paths are gone. Source now is
   portable + data lives in `bot-binding.db` only.

3. **Source-tree slimming** — removed 17 temporary debug / patch /
   compare- scripts from `scripts/` plus 6 draft docs from `docs/drafts/`
   that should never have been in the public release.

4. **Operator-neutral URLs** — `pyproject.toml` author + project URLs
   point to the public GitHub repository, not any single operator.

## ACL v1.2 hardening details

See `docs/acl-v1.2-hardening.md` for the design discussion. Highlights:

| Change | Why |
|---|---|
| `astor_init_acl` validates actor against a strict regex | Typos and smuggling attempts fail at init, not later |
| `actor`/`role` consistency check | Cannot impersonate (e.g. actor=first_admin role=user) |
| `user_id` format check (`[A-Za-z0-9_-]{1,64}`) | Caller bugs surface at init |
| Re-init with different actor writes audit row | Silent privilege escalation cannot hide |
| `tier='public'` write restricted to first_admin + admin | Compromised user/system context cannot spam public |
| `user_id=None` for tier=private/repo raises `PermissionError_` | Caller bugs surface, no silent pass |
| `_CURRENT` backed by ContextVar (read) + threading.local (fallback) | asyncio per-task isolation |
| Per-(actor, target, action) leaky bucket (5 burst, 5/s refill) | Brute-force against one target cannot drain other targets |
| Global ceiling (50 grant checks per second, process-wide) | Co-ordinated flood across many (actor, target) pairs still rate-limited |
| `_canonicalize_user_id` rejects `/`, `\\`, NUL, `\n`, `\r`, `\t`, leading `.`, `..` | Path traversal defense at the ACL boundary |

## Source-tree slimming details

### Removed `scripts/` (17 files)

All of these were one-time debug / patch / A-B-test helpers that
finished their job in the v1.2.7 → v1.10.9 series. They should never
have shipped in the first place.

- `add_caller_ts.py`
- `debug_gemini_fail.py`
- `glm45_vs_g37.py`, `glm53_debug.py`, `glm53_final.py`, `glm53_strict.py`,
  `glm_vs_g37_extract.py`, `glm_vs_g37_v2.py`
- `m3_diag.py`, `m3_vs_g37_multihop.py`
- `patch_expansion.py`, `patch_multihop.py`, `patch_multihop_v2.py`,
  `patch_server_v1109.py`, `patch_stage_recall.py`, `patch_temporal_anchor.py`,
  `patch_v1109_final.py`
- `scenario_clustering.py` (kept `scenario_clustering_v2.py` which is
  the real production version, now refactored to use `ASTOR_DIR` env var)

`scripts/check_bot_binding_invariants.py` is kept (permanent monitor).

### Removed `docs/drafts/` (6 files)

All from the 2026-08-19 → 2026-08-25 design iteration. They were
drafts at the time and should have been archived, not published.

## Upgrade path

```bash
pip install --upgrade astor-memory==1.12.0
astor-server --host 127.0.0.1 --port 7803
```

No database migrations required. The ACL changes are additive; existing
callers that pass canonical arguments continue to work. Callers that
were relying on silent-pass behavior for pathological inputs will now
fail loudly at first contact — which is the goal.
