## S17 - astor_weekly_review cron + send_to_platform.py Telegram fix (R-class T)

**Root cause**: astor-weekly-review-mon-0000utc cron failed every run since 2026-09-07. Three-layer bug:
1. astor_weekly_review.py called `send_to_platform.py` with positional message arg, but argparse expects `--text`
2. subprocess didn't pass HERMES_ENV env var, so send_to_platform.py couldn't load TELEGRAM_BOT_TOKEN
3. send_to_platform.py telegram used `parse_mode=Markdown` which fails on long user-generated text with `_` `*` `|` special characters

**Fixes**:
- astor_weekly_review.py: positional `message` to `--text message` arg
- astor_weekly_review.py: set `HERMES_ENV = ~/.hermes/.env` fallback in import scope
- send_to_platform.py: payload `parse_mode: "Markdown"` removed (plain text default)

**Verified**: `astor_weekly_review.py --days=7` rc=0, msg sent to telegram admin 448594240.

R-class T locked: Telegram send_to_platform.py default parse_mode=None (plain text) not Markdown - Markdown strict mode too fragile for long user-generated text.
