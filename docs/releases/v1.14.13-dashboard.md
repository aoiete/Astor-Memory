# v1.14.13 → v1.14.16 — Dashboard (Web UI for memory health)

## Overview

Four-commit ship (v1.14.13–v1.14.16) that adds a web dashboard for astor-memory.
The dashboard surfaces six dimensions of memory health at a glance and includes a
live Recall debugger for inspecting `/v1/read` output without leaving the browser.

The implementation reuses the warm-orange theme from pokerstats (`#FF8C2E`
accent, `#F5EAD6` bg, `#FFD9B8` border) for visual consistency across the
operator's two web apps.

## Why now

After 4 ship cycles of v1.14.9-12 (PII cleanup, importance audit, skill
extraction, client SDK, integration docs), the system had 10,492 active facts
and 39 baseline eval runs — but the only way to inspect health was CLI + DB
queries. The dashboard gives a 1-screen overview + a live recall debugger that
makes spotting broken queries immediate.

## Ship contents

### 1. `astor_memory/dashboard_data.py` (v1.14.13)

Aggregator module — pure Python stdlib + sqlite3. Six dimensions:

- **hero**: total_users / active_facts / tombstoned / high_importance /
  last_event_minutes_ago / trend_status
- **eval_trend**: 30d window stats (hit_rate / mrr / p95 latency) +
  per-variant latest run + delta vs earliest
- **per_user**: top 16 users by active fact count
- **growth_30d**: daily promoted count (admin) — last 14d
- **top_keywords**: top 20 from `canonical.keywords` JSON column
- **recent_facts**: last 5 promoted facts
- **importance_histogram**: critical (≥0.9) / high (0.7-0.9) / mid (0.5-0.7) /
  low (<0.5) buckets
- **health**: embedding_failed / audit_warnings / audit_total

CLI: `python -m astor_memory.dashboard_data [astor_dir]`

### 2. `astor_memory/server.py` — `/v1/dashboard` endpoint (v1.14.14)

New Flask route registered in `url_map`. Returns the dashboard payload with
a `_cache` field (`hit` or `miss`) so the UI knows whether the response was
served from the 5-min in-process cache.

Module-level `_DASHBOARD_CACHE` dict + `_DASHBOARD_TTL_SEC = 300` — avoids
re-aggregating 16 user dbs per page poll (each poll would otherwise trigger
~6 SQL queries per user).

Optional `?astor_dir=<path>` query override for testing.

### 3. `astor_memory/dashboard/` static assets (v1.14.15 + v1.14.16)

New directory with three files:

- **index.html** — 6-card layout: hero row, eval+growth, per-user+importance,
  keywords+recent, recall-debug+health
- **style.css** — warm-orange theme (CSS vars), responsive (4-col hero → 2-col
  on mobile ≤720px), Chart.js wrapper fixed-height 220px/180px
- **app.js** — vanilla fetch + Chart.js 4.4.1 (jsdelivr CDN). 60s polling,
  destroys+recreates chart instances to avoid memory leak, XSS-safe
  `escapeHtml` on all user content

**Recall Debugger** (v1.14.16): live `POST /v1/read` with `{query, tier, user,
top_k}`. Renders rank + similarity + meta line (fact_id, sim, imp, conf,
score_kind, topic) + content. Enter key triggers Run. Empty results show a
"No matches" hint with query echo.

### 4. `astor_memory/server.py` — static routes (v1.14.15)

Three new Flask routes:
- `GET /dashboard/` and `/dashboard/index.html` → serve `index.html`
- `GET /dashboard/<path:filename>` → serve `style.css` or `app.js`

Uses Flask `send_from_directory` (no path traversal risk).

## Server restart required?

**No.** The endpoint + static routes are in `astor_memory/server.py` which
is imported by the running server. To activate, restart `astor_memory` (NSSM
service). Until restart, the endpoint will return 404 but no existing
functionality is broken. R218 (gateway no-restart) applies; recommend
restarting at next maintenance window.

## Known limitations

1. **Recall debugger only has 1 user hardcoded** (admin). Future: dynamically
   populate from `/v1/health/private?user=...` or a new `/v1/users` endpoint.
2. **Chart.js via CDN** — no offline mode. Acceptable for an operator-only
   dashboard; can vendor later if needed.
3. **No PII on dashboard itself** — but admin's recent_facts may leak PII
   that was previously written. The dashboard assumes the operator has
   already audited what got into admin tier. Recommend running
   `scripts/astor_initial_report.py` to spot-check before exposing.
