## 3. 新的 4 层记忆栈 / The new 4-tier memory

之前是单一数据库，什么都往里塞。 现在是 4 层：

|层 | 名字 | 内容 | 通俗解释 |
|---|------|------|----------|
| **L0** | Raw Events | 每一条对话、工具调用、回复 | 原始聊天记录，像日记本 |
| **L1** | Atomic Facts | 从原始对话提炼出的"重要事实" | 提炼出"key takeaways"，可被引用 |
| **L2** | Scenarios | 同话题的 facts 聚类成"场景" | 把 facts 按主题归档成文件夹 |
| **L3** | User Profile | 长期偏好、习惯、身份 | 永久用户画像 |

**每层做什么**：
- **L0 (原始事件)**：每次对话、每个工具调用、每个回复都自动 log 进去。 像日记本一样，全部留底。
- **L1 (原子事实)**：从 L0 提炼出"可以重用的 fact"。 比如你说"我喜欢黑咖啡不糖不奶"，这就是一条 L1 fact。
- **L2 (场景归类)**：同话题的 facts 聚类成"场景"。 比如"trading"、"astor memory"、"咖啡偏好" 会各自成一组。
- **L3 (用户画像)**：长期偏好 + 习惯 + 身份。 这一层是 astor-memory 自己的 profile forge 自动生成的，不依赖外部 SDK。

**4 层的构想**：L0 是"原始信号"，L1 是"提炼出的知识"，L2 是"按主题归档"，L3 是"关于你这个人的总结"。 bot 用 L1 调上下文，看 L2 知道聊到哪个话题，用 L3 调整语气和内容。

## 4. 多源路由 / Multi-source routing

之前：每个存储独立，没有协调。 现在：3 个 store 各司其职，1 个 query 同时拉，自动排序：

| Store | 干什么 |
|-------|------|
| **bus** | 事件流 + 原子事实（结构化、可审计） |
| **nest** | 向量索引（语义检索，"找到相似话题"） |
| **forge** | profile forge（用户画像 + 个性化） |

**3 个 store 的协作**：你问"Hermes，我之前让你分析过什么"，bus 找结构化事件，nest 找相似话题，forge 找相关 user context。 三层同时拉，按相关度排序，返回最相关的 top 几条。 这样既不会因为纯 vector 拉错，也不会因为纯 keyword 漏掉。

## 5. 性能与稳定性 / Performance & stability

| 指标 | 之前 | 现在 | 改善 |
|------|------|------|------|
| Recall 噪声率 | 60-80% | ≤10% | ↓ 50% |
| Recall 速度 | ~3.4 秒 | ~1-2 秒 | ↓ 50% |
| Prompt cache 命中率 | 不稳定 | 98-100% | 稳定 |
| 冷启动时间 | ~14 秒 | <2 秒 | ↓ 85% |
| 长对话速度 | 越聊越慢 | 最后一句跟第一句一样流畅 | 不掉 |
| Hygiene 频率 | 等消息触发 | 每 4 小时自动 | 持续 |
| Crash recovery | 手动 | 5 连 crash 自动 restart | 不用管 |

**性能优化的目标**：让 Hermes 几乎"看不出"在跑 — 不会卡、不会丢、不会记错。

**实际感受**：系统挂了不用怕，记忆不会丢。
